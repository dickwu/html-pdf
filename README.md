# ironpress-php

PHP extension for Ironpress, implemented in Rust with ext-php-rs.

## Requirements

- PHP 8.1+
- `php-config` / PHP development headers
- Rust toolchain
- Clang
- `cargo-php` for convenient install and stub generation

## Build

```sh
cargo build --release
```

## Test Without Installing

```sh
php -d extension=./target/release/libironpress_php.so tests/smoke.php
php -d extension=./target/release/libironpress_php.so tests/options.php
```

On macOS, Cargo builds `./target/release/libironpress_php.dylib`:

```sh
php -d extension=./target/release/libironpress_php.dylib tests/smoke.php
php -d extension=./target/release/libironpress_php.dylib tests/options.php
php -d extension=./target/release/libironpress_php.dylib tests/stamper.php
php -d extension=./target/release/libironpress_php.dylib tests/merge.php
```

Add `-n` when a Homebrew build of the extension is already loaded from
`conf.d`, otherwise PHP warns that the module is loaded twice and keeps the
installed one.

The merge matrix needs `qpdf`, poppler (`pdfinfo`, `pdftotext`, `pdfimages`,
`pdftoppm`), ImageMagick and ghostscript, plus Python `reportlab` for some
fixtures. It generates synthetic PDFs (about 60 MB with `--large`) into an
ignored build directory, checks every merged page against its source and
against the PNGs in `tests/fixtures/merge/golden/`, and prints a table:

```sh
python3 tests/fixtures/merge/generate.py tests/fixtures/merge/build --large
php -n -d extension=./target/release/libironpress_php.dylib tests/merge-matrix.php tests/fixtures/merge/build
# after an intended rendering change: add --update-goldens
```

## Install Into Current PHP

```sh
cargo install cargo-php --version 0.2.1 --locked
cargo php install --release --yes
php -m | grep ironpress
```

On macOS, if `cargo-php` fails to install because the PHP symbols are unresolved during linking, install it with PHP's extension linker mode:

```sh
RUSTFLAGS='-C link-arg=-Wl,-undefined,dynamic_lookup' cargo install cargo-php --version 0.2.1 --locked
```

## Install With Homebrew

```sh
brew tap dickwu/tap
brew install dickwu/tap/html-pdf
php -m | grep ironpress_php
```

The Homebrew formula detects installed Homebrew PHP formulae at install or upgrade time, builds a matching extension for each PHP minor version, and writes:

```text
$(brew --prefix)/etc/php/<php-minor>/conf.d/ext-ironpress_php.ini
```

Reinstall `html-pdf` after installing another Homebrew PHP version. Restart long-running PHP processes after installing or upgrading the formula.

## Generate Stubs

```sh
cargo php stubs -o ironpress_php.stub.php
```

## Release

Releases are tag-driven. After bumping the version and committing the change:

```sh
git tag v0.1.0
git push origin main v0.1.0
```

GitHub Actions verifies Linux and macOS builds, creates the GitHub release, generates the Homebrew formula from the tag tarball, and pushes it to `dickwu/homebrew-tap`. The release workflow requires the `HOMEBREW_TAP_DEPLOY_KEY` repository secret, which is the private half of a read-write deploy key installed on `dickwu/homebrew-tap`.

## API

```php
<?php

$pdf = ironpress_html_to_pdf('<h1>Hello</h1><p>World</p>');
file_put_contents(__DIR__ . '/hello.pdf', $pdf);

ironpress_html_to_pdf_file('<h1>Hello</h1><p>Saved directly</p>', __DIR__ . '/hello-direct.pdf');

$mdPdf = ironpress_markdown_to_pdf("# Hello\n\nGenerated from **Markdown**.");
file_put_contents(__DIR__ . '/markdown.pdf', $mdPdf);

$converter = new Ironpress\HtmlConverter();
$converter->pageSize('letter');
$converter->landscape(true);
$converter->margin(36.0);
$converter->header('Report');
$converter->footer('Page {page} of {pages}');

$pdf = $converter->convert('<h1>Quarterly Report</h1><p>Generated by Ironpress PHP extension.</p>');
file_put_contents(__DIR__ . '/report.pdf', $pdf);

$converter->addFont('Inter', file_get_contents(__DIR__ . '/fonts/Inter.ttf'));
$pdf = $converter->convert('<p style="font-family: Inter">Custom font text</p>');
```

### Table-cell metrics

Tables are measured the way ironpress-php 0.2.x measured them, so layouts tuned
against 0.2.x keep their page breaks: collapsed borders take no layout space,
only a cell's first-top and last-bottom child margins are kept, and tables get
no default `border-spacing`. The `ironpress_*` functions use the same default.
Call `$converter->legacyTableCellMetrics(false)` for Chromium-like table-cell
metrics instead.

### Stamping an existing PDF

`Ironpress\PdfStamper` writes text and tick marks on top of the pages of an
existing PDF (a government form, a signed template) without altering the
original page content. Coordinates are PDF points with `y` measured from the
top edge of the page: `text()` takes the baseline, `check()` the top-left
corner of the box. Text uses the built-in Helvetica / Helvetica-Bold, or a
TrueType font added with `addFont()`, always with WinAnsi encoding; characters
outside that repertoire, or missing from an added font, throw instead of
printing a `?`.

```php
$stamper = new Ironpress\PdfStamper(file_get_contents('form.pdf'));
$stamper->pageCount();                       // 3
$stamper->pageSize(1);                       // [612.0, 792.0]
$stamper->text(1, 59.0, 230.8, 'Doe');       // page, x, baseline-from-top, text
$stamper->text(1, 127.0, 655.0, '2026-10-05', 9.0, 'Helvetica', 'center');
$stamper->text(1, 343.0, 241.6, $providerLine, 9.0, 'Helvetica-Bold', 'left', 216.0); // shrinks to fit 216 pt
$stamper->check(1, 56.2, 146.2, 10.8);       // tick inside the 10.8 pt box at (x, y-top)
$stamper->addFont('Signature', file_get_contents('Allura-Regular.ttf')); // a .ttf, embedded whole
$stamper->text(1, 236.9, 463.1, 'Jane Doe', 16.0, 'Signature');
file_put_contents('filled.pdf', $stamper->toPdf());
$stamper->reset();                           // reuse the template for the next client
```

`toPdf()` leaves the template and the queued operations untouched, so one
loaded template can be filled many times. Added fonts stay through `reset()`
and are embedded once per PDF, only when a text uses them. Only TrueType
outlines (`glyf`) are supported; `.otf` (CFF) fonts, font collections and
fonts whose licence forbids embedding (OS/2 `fsType` restricted) are refused.

### Merging PDFs

`Ironpress\PdfMerger` appends the pages of other PDFs (scans, lab reports,
attachments from any producer) to a PDF, typically one ironpress just made.
Each page keeps its size, rotation, fonts and images, including attributes it
inherits from its page tree.

```php
$merger = new Ironpress\PdfMerger(ironpress_html_to_pdf($html));
$merger->maxPages(500);               // default 5000
$merger->maxInputBytes(50 << 20);     // per input, default 128 MiB
foreach ($attachments as $pdf) {
    try {
        $merger->append($pdf);       // returns the number of pages added
    } catch (Ironpress\EncryptedPdfException $e) {
        // password-protected (code PASSWORD_PROTECTED) or
        // owner-restricted (code OWNER_RESTRICTED); skip or ask for a copy
    } catch (Ironpress\InvalidPdfException $e) {
        // EMPTY, NOT_PDF, CORRUPT or NO_PAGES
    }
}
file_put_contents('out.pdf', $merger->toPdf());

// or all at once; the message names the failing index ("PDF #2: ...")
$pdf = ironpress_pdf_merge([$first, $second, $third]);
```

All errors extend `Ironpress\PdfMergeException` (itself an `\Exception`),
and `getCode()` is one of its constants. A rejected input leaves the merger
exactly as it was, so the remaining inputs can still be appended. Size and page
limits throw `Ironpress\PdfLimitException`. The exception classes are thrown
by the extension only; PHP code cannot `new` them.

PDFs that open without a password but carry owner restrictions (no printing,
no copying) are rejected by default because the merged copy would not keep the
restrictions; call `allowOwnerRestricted(true)` to accept them.

Only pages are merged. Bookmarks, form-field trees (widgets still show but are
no longer fillable), named destinations, tagged-PDF structure and optional
content of appended PDFs are dropped, and identical fonts or images in several
inputs are stored once per input.

## Security Defaults

HTML sanitization is enabled by default. Call `sanitize(false)` only when the input is trusted.

Remote resource loading is not enabled by default. The extension only compiles remote URL support when built with the `remote` feature:

```sh
cargo build --release --features remote
```

Do not add browser, `wkhtmltopdf`, Chromium, Playwright, or Puppeteer runtime dependencies; Ironpress renders through its Rust layout engine.
